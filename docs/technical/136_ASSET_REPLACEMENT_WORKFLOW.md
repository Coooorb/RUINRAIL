# Asset Replacement Workflow

> **Status:** Operational pipeline document adopted by TASK 151.
> **Scope:** How a final production asset enters the repository and replaces a placeholder. It changes no gameplay rule, no content count and no stable ID.

## 1. The Guarantee

A new approved asset can be added or replaced **without touching gameplay code**.

That holds because every asset binds through a seam that already existed at TASK 148. Role IDs come from the definitions and code constants that gameplay already uses — `WeaponDefinition.Id`, `AudioEventIds.Required`, `MusicRole`, `Biome`, `CharacterAnimationSet.ActorId` — so an asset is wired to a role, never to a path, a display name or an index. Replacing the asset behind a role leaves every serialized reference, save file and network ID untouched (coding rule 9).

## 2. Where Things Live

`AssetNamingConvention` is the single source of truth for placement. It derives the path from the stable role ID, so the same role always resolves to the same file. The existing asset roots are reused; no parallel root was created.

| Category | Convention path | Binding point |
|---|---|---|
| Character sheets | `Assets/Game/Art/Characters/{actor}/{actor}_sheet.png` | `CharacterAnimationSet` clips |
| Animation sets | `Assets/Game/Art/Characters/{actor}/{actor}_animation_set.asset` | `CharacterAnimationSet.ActorId` |
| Weapons | `Assets/Game/Art/Weapons/{weaponId}.png` | `WeaponVisualDriver` on the WeaponPivot |
| Item icons | `Assets/Game/Art/Icons/Items/{itemId}.png` | `ItemDefinition` icon field — **seam missing, see §6** |
| Biome tiles | `Assets/Game/Art/Tiles/{Biome}/{biome}_{category}.png` | `Tile` asset referenced by baked room prefabs |
| Biome props | `Assets/Game/Art/Props/{Biome}/{package}/` | Room prefab `SpriteRenderer`s on approved sorting layers |
| Biome lighting | `Assets/Game/ScriptableObjects/Presentation/Lighting_{Biome}.asset` | `BiomeLightingProfile` (tuned in place, GUID kept) |
| World objects | `Assets/Game/Art/World/{role}.png` | `SpriteRenderer` on the existing runtime component |
| UI sprites | `Assets/Game/Art/UI/{role}.png` | `UiKit` / the owning view |
| Pixel font | `Assets/Game/Art/Fonts/ruinrail_pixel.ttf` | `UiKit.Font()` |
| VFX | `Assets/Game/Art/Vfx/{kind}.png` | `EffectPool.Spawn` kind |
| SFX | `Assets/Game/Audio/Sfx/{event_id}.wav` | `AudioEventDefinition.Clips` in `AudioEventCatalog` |
| Music / stingers / ambience | `Assets/Game/Audio/{Music,Stingers,Ambience}/{role}.ogg` | `MusicCatalog` entry |
| Network player prefab | `Assets/Game/Prefabs/Network/PlayerNetworkEntity.prefab` | `NgoPlayerEntityFactory` + `DefaultNetworkPrefabs.asset` |

Naming is lowercase and underscore-separated. A dot in a role ID becomes an underscore, so `weapon.fire.pistol` → `weapon_fire_pistol.wav`. `TestResults/completion_asset_manifest.md` (regenerated by `CompletionAssetManifest`) prints the expected path and binding point for all 306 roles.

## 3. Import Metadata

Sprites import per `art/107 §3`: Sprite type, **PPU 32**, **Point** filter, **Uncompressed**, **no mip maps**, alpha-is-transparency on. This is what `PlaceholderTileAuthoring` already does, so final art imports exactly like the placeholder it replaces.

Slicing rules per category:

- **Character sheets** — Grid by cell. Eight rows, one per `BodyFacing8` in enum order; columns are frames. Cell size is the actor's canvas from `art/106 §3`.
- **Weapons** — Single sprite drawn pointing **+X (east)**. `WeaponVisualDriver` rotates it through 360°; never author per-angle variants.
- **Tiles** — Exactly 32×32 on the grid. Multiple only when a role ships a variant set.
- **UI frames and bars** — Set the sprite border so they 9-slice; do not author one sprite per size.
- **VFX** — Multiple when the effect is a frame strip; frames read left to right.
- **Audio** — SFX as `.wav`; music, stingers and ambience as `.ogg`. Ambience and music must be loop-safe; stingers are one-shots and are never looped.

## 4. The Replacement Procedure

1. **Record provenance first.** Add an entry to `production/asset_provenance.json` with role ID, source path, author, provenance and licence. `derivedFromReferenceGame` must be `false` — `art/107 §6` forbids shipping anything derived from a reference game.
2. **Drop the file at its convention path**, from `AssetNamingConvention` or the manifest's *Expected source path* column.
3. **Set import metadata** per §3. Unity's importer is the authority; the validator checks the result.
4. **Bind it at the existing seam** — assign the clip, the catalog entry, the tile sprite. Never add a new lookup path for one asset.
5. **Run the gate:** `RuinRail/Production/Validate Asset Pipeline` (or the EditMode suite). Zero problems is required.
6. **Delete the placeholder** for that role from the release path (`art/106 §13.9`). A role may not resolve to placeholder art and claim final status; the validator fails that combination.
7. **Regenerate the manifest** — `RuinRail/Production/Generate Completion Asset Manifest`.
8. **Human approval** at the TASK 152 / 165 / 176 gate. Only a human sets `approvedBy`. A role reaches `APPROVED` there and nowhere else.

Steps 1–7 are mechanical and checked. Step 8 is judgment and is never automated.

## 5. What The Validator Catches

`AssetPipelineValidator` fails the batch on:

| Failure | Why it matters |
|---|---|
| Role with no stable ID, or no convention path | The asset cannot be replaced without a gameplay change |
| Duplicate role ID, or two roles claiming one file | The second asset silently overwrites the first |
| Wrong PPU, filter, compression or mip maps | Pixel fidelity is destroyed on import, often invisibly in the editor |
| Null sprite, clip frame or audio clip in a binding point | Ships as a silent hole rather than an error |
| Placeholder art in a role claiming `APPROVED`/`INTEGRATED` | Dev art would ship as final content |
| Missing or incomplete provenance on a final role | No record of where the asset came from or under what licence |

It reports the offending path **and** the role that caused it. It does not judge quality — that is `art/107 §5` steps 4 and 5.

## 6. Known Seam Gap

`ItemDefinition` has **no icon or sprite field**. Weapons, armor, accessories, consumables and ammo therefore have a convention path but no binding point in code. **TASK 158 must add that narrow seam** — a serialized sprite reference on the item definition — before any of the 72 item icon roles can be integrated. It is a field addition on an existing definition, not a new system, and it changes no ID and no balance value.

This is the one place where §1's guarantee does not yet hold, and it is recorded in `TestResults/completion_asset_manifest.md` (regenerated by `CompletionAssetManifest`) rather than worked around.
